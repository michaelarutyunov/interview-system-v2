| File | Lines | Diagnostic |
|------|-------|------------|
| `src/services/methodology_strategy_service.py` | 308, 310 | `reportGeneralTypeIssues`, `reportArgumentType` |

**Context:**
```python
for strat, score in ranked_conv:
    all_ranked.append((strat, None, score))

```
`rank_strategies` returns `List[Tuple[StrategyConfig, float]]` for conversation-level strategies, but `all_ranked` expects `List[ScoredCandidate]` and `all_decomposition` expects `List[ScoredCandidate]` decomposition items. The tuple unpack works at runtime but violates the declared type contract.

**Root Cause:** The return type of `rank_strategies` is not unified across node-pair and conversation-only code paths, or `ScoredCandidate` does not accommodate the raw `(StrategyConfig, float)` tuple.

**Recommendation:**
- Option A: Change `rank_strategies` to always return `List[ScoredCandidate]` (or equivalent structured object) and update both call sites.
- Option B: Add an explicit conversion step before appending to `all_ranked`/`all_decomposition`:
  ```python
  scored = [ScoredCandidate(strategy=strat, node_id=None, score=score) for strat, score in ranked_conv]
  all_ranked.extend(scored)
  ```

### 3.3 Untyped Pandas Usage in Analysis Scripts

#### `scripts/diagnostics/analyze_signal_redundancy.py` (16 errors)
Errors include calling DataFrame methods (`groupby`, `drop_duplicates`, `isin`, `empty`, `index`) on variables typed as `ndarray`, a return type mismatch (`tuple[Series, Series]` vs `Series`), and incorrect `rename` signatures.

**Root Cause:** Data loaded via `pd.read_csv` is not explicitly asserted to be a `DataFrame`, so pyright conservatively infers `ndarray | DataFrame | Any`. Subsequent method calls fail because `ndarray` lacks those attributes.

**Recommendation:** After each `pd.read_csv` call, add an explicit type assertion:
```python
df = pd.read_csv(path)
assert isinstance(df, pd.DataFrame)
```
Alternatively, annotate the variable: `df: pd.DataFrame = pd.read_csv(path)`.
Also fix the `rename` call (pandas `rename` expects a mapping or callable, not a plain string).

#### `scripts/reporting/generate_reviews.py` (38 errors)
This script has the same pattern as `analyze_signal_redundancy.py` but amplified: heavy use of pandas without type narrowing leads to `ndarray` inferences and cascading attribute-access errors (`fillna`, `groupby`, `sort_values`, `drop_duplicates`, `unique`, etc.).

**Root Cause:** The script treats intermediate variables as DataFrames/Series, but pyright cannot prove they are not `ndarray` due to untyped pandas APIs and chained operations.

**Recommendation:**
- Add `assert isinstance(..., pd.DataFrame)` or `assert isinstance(..., pd.Series)` after key transformation points.
- Break long pandas chains into named intermediate variables with explicit type annotations.
- For `sort_values` errors, verify that the caller is a DataFrame/Series (some grouped objects may not support the same overloads).

#### `scripts/diagnostics/extract_simulation_data.py` (1 error)
| File | Line | Diagnostic |
|------|------|------------|
| `scripts/diagnostics/extract_simulation_data.py` | 240 | `reportCallIssue` on `sort_values()` |

**Context:** `sort_values()` is called with no arguments on a type pyright cannot resolve as a sortable DataFrame/Series.

**Recommendation:** Verify the variable type at line 240. If it is a DataFrame, add `assert isinstance(obj, pd.DataFrame)` before the call.
